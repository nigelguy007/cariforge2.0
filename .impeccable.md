# Impeccable — Design Context

Synthesized from direct, explicit statements made across an extended live
design conversation for this project (not inferred from the codebase) —
see git log on `mission-pipeline-rebuild` for the full history. Covers the
`/` homepage specifically; the rest of the app (dashboard, missions, gates)
uses a separate light-first emerald system (`src/app/custom-style.css`).

## Design Context

### Users
Regulated-industry buyers evaluating CARI Forge as a governed, human-gated
AI software-delivery platform (EU AI Act Article 12/14 positioning) — not
consumer users. They arrive skeptical of AI-hype marketing and are
specifically reassured by evidence of human control (named approvers,
typed reasons, audit trails), not by flashy visuals.

### Brand Personality
Explicit user description, verbatim: **"corporate and easy to use with a
caribbean influence in colour."** Explicitly rejected: a fully saturated
teal wash (called "revolting") and, separately, a fully saturated emerald
wash (still "not professional") as PAGE-WIDE treatments — the lesson taken
was that full-bleed saturated color reads as marketing/flashy regardless
of hue, which the real CARI Forge platform's own precedent confirms (it
moved to a light, restrained register after benchmarking Lindy, Linear,
Relevance AI, Gumloop). Three words: **governed, restrained, coastal.**

### Aesthetic Direction
**Superseded, current as of the latest explicit instruction**: "the
texture and contrast of apple.com... keeping a caribbean sea colour."
This is a deliberate, named reference to Apple's actual product-page
language — not a synonym for "clean SaaS" or "light mode." Concretely:
huge, confident sans-serif type at a scale most sites don't dare (headline
sizes that fill the viewport width), enormous whitespace/negative space
as the primary compositional tool, off-white/white fields (not dark
hero sections), soft/subtle elevation (gentle shadows and blur, never a
hard drop-shadow or a visible card border doing the work), restrained
near-monochrome base with the brand colour appearing as a rare, confident
accent (one hero moment, a button, a highlight) rather than a background
wash. Caribbean-sea colour (aquamarine/turquoise, brand-h≈188) is now the
ACCENT within that Apple-style restraint, not the dominant field colour —
this is a real reversal from the immediately preceding several passes,
which pushed the opposite direction (full-page, increasingly bright,
increasingly saturated colour fields). That earlier direction was itself
a direct, repeated, explicit response to "too dark" / "brighter" / "much
brighter" feedback — the Apple reference is a NEW, separate instruction on
top of that, not a retraction of it, so the accent itself should stay
vivid/bright where it appears; it's the proportion of the page it covers
that changes.

Historical anti-references (still valid, now for a different reason):
generic "AI SaaS" hype pages (gradient-text headlines, neon-on-black
glow-everywhere, cyan-on-dark as the whole palette) — same lesson as
before (color as ambient wash reads as generic/AI-generated), now
reinforced by "look like Apple," which is itself built on restraint.

**Accent hue, current**: sourced explicitly from a named reference —
https://icolorpalette.com/palette-by-themes/caribbean/ ("pick the best
colour palette from this website... it must retain the apple look just
be in a different colour"). Of the real, extracted swatches on that page
(read via their own listed hex values, not guessed), the clear standout
was #1257cc from a white-sand-beach photo palette (paired there with
#7ec833/#98bc4a greens, #f5f5f1/#c8cfc1 neutrals) — a vivid, saturated
royal/cobalt blue (OKLCH ≈ L0.49 C0.193 H261), converted by hand from
its sRGB hex, not estimated. Picked over the page's other palettes
because every other visible option was muted/earthy (dusty tans, sage
greens, greyed-out teals) — #1257cc was the only swatch vivid enough to
carry a "hero accent" role the way Apple's own blue link colour does.
This is deliberately a different colour FAMILY from the aquamarine/teal
this project settled on before (H≈188, blue-green) — H≈261 is a true
blue, leaning slightly toward violet, per the explicit "different
colour" instruction — not a refinement of the teal, a replacement.

### Design Principles
1. **Tint, never pure.** No `#000000`/`#ffffff` as large-surface colors —
   every dark surface carries a low-chroma lean toward the brand hue.
2. **Accent is rare, not ambient.** Color pops at 2-3 deliberate moments
   (primary CTA, one text emphasis, nav identity) — not glowing on every
   hover state at once.
3. **Solid color for emphasis, not gradient fill.** Weight, size, and a
   single considered color communicate importance; gradient text reads as
   an AI-generated hero page, which is exactly what this audience is
   trained to distrust.
4. **Glass where it was asked for, not as a reflex.** The user explicitly
   requested a "liquid glass effect" for nav/surface chrome in this same
   conversation — that's honored as a deliberate, human-requested choice,
   not re-derived as a generic AI decorative default.
5. **Corporate and easy to use wins ties.** When a bolder vs. a more
   restrained option are both defensible, pick the one a skeptical
   regulated-industry buyer would trust on first look.
6. **Apple-style texture (current, see Aesthetic Direction above).**
   Whitespace is the primary tool, not color. Type scale should feel
   oversized/confident, not merely "large." Depth comes from soft blur/
   shadow, never a hard border doing the separating work. The accent
   colour gets ONE clear hero moment plus incidental use in interactive
   elements (buttons, links) — never a field/background wash.
